# Report di test — Interfaccia web EarnSight

**Data:** 2026-09-22
**Ambiente testato:** stack Docker locale (`docker compose`) — frontend Streamlit (`localhost:8501`) + backend FastAPI (`localhost:8000`)
**Metodo:** navigazione reale del browser (Chromium headless via Playwright), non solo chiamate API — click, upload file, compilazione form, screenshot ad ogni step.

## Esito complessivo

Sono stati trovati **2 bug bloccanti** che mandavano in crash rispettivamente la pagina *Cedolini* (aperta da Documenti) e l'intera pagina *Impostazioni*. Entrambi sono stati **corretti e verificati** con un secondo giro di test end-to-end. Il resto del flusso applicativo (login, upload, estrazione, revisione campi, correzioni) funziona correttamente.

## Bug trovati e risolti

### 1. Crash aprendo un documento da "Documenti" → `StreamlitPageNotFoundError`

- **File:** [frontend/pages/home.py:27](../frontend/pages/home.py#L27)
- **Sintomo:** cliccando il pulsante "Apri" su una card documento, l'app va in crash con `streamlit.errors.StreamlitPageNotFoundError: Could not find page: 📄 Cedolini`, rendendo impossibile aprire il dettaglio di un documento da quella scorciatoia.
- **Causa:** `st.switch_page("📄 Cedolini")` passava una stringa (titolo + icona) come identificativo pagina. Nel progetto le pagine sono definite tramite `st.Page(callable, ...)` (funzione, non file): Streamlit richiede in questo caso lo stesso oggetto `Page` passato a `st.navigation`, non una stringa.
- **Fix:** creato un registro condiviso `frontend/lib/nav.py` (`PAGES: dict[str, st.Page]`), popolato da `app.py` al momento della creazione delle pagine e importato da `home.py` per passare l'oggetto `Page` corretto a `st.switch_page(PAGES["documents"])`.
- **Verifica:** ricostruito il container frontend, ripetuto il click su "Apri" → naviga correttamente alla pagina Cedolini senza errori, nessun errore in console.

### 2. Crash sistematico della pagina "Impostazioni" → `StreamlitInvalidParameterTypeError`

- **File:** [frontend/pages/settings.py:31](../frontend/pages/settings.py#L31) (riga pre-fix)
- **Sintomo:** la pagina Impostazioni non si apriva mai, mostrando sempre `streamlit.errors.StreamlitInvalidParameterTypeError: Invalid index type. Expected one of: int, None. Provided type: str.` — impossibile configurare o anche solo visualizzare il provider LLM.
- **Causa:** `index=[k for k, v in PROVIDERS.items() if v == ...][0]` restituiva la **label** del provider (es. `"Ollama (locale)"`), non la sua **posizione** nella lista, mentre `st.radio(index=...)` richiede un intero.
- **Fix:** calcolata la posizione con `list(PROVIDERS.values()).index(...)`, con fallback a `0` se il valore salvato non corrisponde a nessun provider noto (evita anche un possibile `IndexError` su dati legacy/inattesi).
- **Verifica:** pagina Impostazioni si apre correttamente con la selezione di default giusta ("Nessuno" quando non configurato); testato salvataggio e persistenza sia per provider "Ollama" che "OpenAI" (incluso il campo API key) — ricaricando la pagina il provider salvato resta selezionato correttamente.

Entrambi i fix sono passati anche da `ruff check frontend/` (nessun errore di stile) e la suite di test backend (`pytest tests/`, 36 test) continua a passare invariata.

## Funzionalità verificate come corrette

- **Login:** credenziali errate → messaggio d'errore corretto senza crash; credenziali corrette (da `.env`: `admin` / `change-me`) → accesso regolare.
- **Upload multiplo PDF** (cedolino valido, cedolino con importi incongruenti, scan senza testo) con elaborazione asincrona e refresh automatico dello stato.
- **Rilevamento stato documento:** `done`, `needs_review`, `needs_ocr` mostrati correttamente con badge colorati coerenti.
- **Pagina Cedolini:** dettaglio con metriche (lordo/trattenute/netto), tabella competenze/trattenute, confidenze estrazione, testo estratto e JSON grezzo — tutto corretto sul documento valido.
- **Pagina Revisione:** rileva correttamente l'incongruenza lordo/trattenute/netto, mostra il campo di correzione, disabilita "Risolvi con LLM" quando nessun provider è configurato; la correzione manuale salva, rivalida e il documento sparisce dalla lista "da revisionare" una volta risolto.
- **Pagina Impostazioni** (dopo il fix): selezione provider, salvataggio, persistenza tra i reload.
- **Logout:** pulisce la sessione e torna al login.
- Nessun errore in console del browser o richieste HTTP fallite durante la normale navigazione via sidebar.

## Osservazione minore (non bloccante, nessun fix applicato)

- Caricando **direttamente** un URL profondo (es. `localhost:8501/documents`, refresh di pagina su una sotto-pagina) si osservano due 404 innocui (`/documents/_stcore/health`, `/documents/_stcore/host-config`) prima che Streamlit si autocorregga. È un comportamento noto del client-side routing di Streamlit su URL "deep-linked", non causato dal codice applicativo: la pagina si carica comunque correttamente (con richiesta di login se la sessione non è attiva, come atteso). Non richiede intervento.

## Fuori scope / limiti del test

- Il flusso **OCR** per PDF senza layer di testo è intenzionalmente non implementato ("componente futura", come indicato nel messaggio a UI) — comportamento verificato come coerente col design attuale, non un bug.
- Il pulsante **"Risolvi con LLM"** è stato verificato solo per abilitazione/disabilitazione in base al provider configurato; non è stata testata una chiamata reale a un LLM (richiederebbe un'istanza Ollama o una API key OpenAI valida).
- Non esiste un endpoint per eliminare un documento: i PDF di test caricati durante questa sessione (`cedolino_test.pdf`, `cedolino_mismatch.pdf`, `scan_blank.pdf`) restano nel database/dev locale insieme ai documenti già presenti (`smoke-payslip.pdf` x2). Da ripulire manualmente se necessario (es. reset del volume `pgdata` o del DB dev).
